# CyberBooking System Backend

Система онлайн-бронирования мест в компьютерных клубах (Computer Clubs Management System).

## Описание
Проект представляет собой монолитный бэкенд на основе **FastAPI**, который предоставляет UI через **Jinja2 шаблоны** и асинхронный доступ к базе данных **PostgreSQL** через **SQLAlchemy 2.0 (asyncpg)**.

## Основной стек технологий
- **Фреймворк:** FastAPI (Python 3.12)
- **База данных:** PostgreSQL
- **ORM:** SQLAlchemy 2.0 + asyncpg
- **Аутентификация:** JWT (HTTPOnly Cookies) и `passlib (bcrypt)`
- **Конфигурация:** `pydantic-settings` (поддержка `.env`)
- **Деплой:** Docker & Docker Compose (`uvicorn` с несколькими воркерами)

## Установка и запуск (Docker)

Для самого простого запуска со встроенной базой данных используйте Docker Compose.

```bash
docker-compose up -d --build
```

Проект запустится на порту `8000`. 
База данных Postgres поднимется на порту `5432`.

### Локальный запуск без Docker

1. Установите зависимости (рекомендуется использовать виртуальное окружение):
```bash
pip install -r requirements.txt
```

2. Укажите правильный путь базы данных (например, поднятой отдельно) в файле `.env` (если он есть), либо установите переменную окружения `DATABASE_URL`. По умолчанию приложение будет использовать `postgresql+asyncpg://postgres:12345678@localhost:5432/club`.

3. Запустите uvicorn (с горячей перезагрузкой):
```bash
uvicorn main:app --reload
```

## Бизнес-логика и особенности

### Сессии и безопасность
Аутентификация реализована полностью *Stateless*. После регистрации и проверки хэшированного bcrypt пароля, генерируется `JWT token`, который записывается клиенту в **HttpOnly** Cookie (`access_token`). 

### Роли
Система поддерживает две роли:
- **admin** (управление клубами, компьютерами, играми и товарами)
- **user** (возможность выбирать клуб, бронировать ПК и покупать товары в баре)

### Бронирование
Компьютеры имеют свойство `status` (`free`, `busy`). Когда место бронируется, оно помечается как `busy` и фиксирует идентификатор пользователя `current_user_id`. Освободить место (`/free_seat/{pc_id}`) может либо сам пользователь, либо администратор платформы.
